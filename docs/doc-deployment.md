## Секреты для подписи

Секреты для подписи хранятся в отдельном репозитории: `git@github.com:easydev991/android-secrets.git` (папка `swparks`).

Команды `make release` и `make apk` автоматически клонируют репозиторий по SSH и загружают секреты в папку `.secrets/` перед сборкой (если `.secrets/` ещё не создана).

## Создание сборки

### Релизный AAB (для публикации в магазине)

Для создания подписанной AAB-сборки выполните:

```bash
make release
```

Команда автоматически:

1. Увеличивает номер сборки (`VERSION_CODE`) на 1
2. Создает подписанную AAB-сборку: `swparks{VERSION_CODE}.aab` (например, `swparks1.aab`, `swparks2.aab`)
3. Отображает версию и номер сборки

### Релизные APK (для распространения вручную)

Для создания подписанных APK есть команда:

```bash
make apk
```

Команда автоматически:

1. Создает два подписанных APK-файла:
   - `swparks{VERSION_CODE}-arm64-v8a.apk` (например, `swparks1-arm64-v8a.apk`)
   - `swparks{VERSION_CODE}-armeabi-v7a.apk` (например, `swparks1-armeabi-v7a.apk`)
2. Отображает версию и номер сборки
3. **Не увеличивает** номер сборки (`VERSION_CODE`)
4. Включает ABI-сплиты через флаг `-PenableSplits=true` — в APK входят только `arm64-v8a` и `armeabi-v7a` (x86/x86_64 исключены, релизные APK не предназначены для эмуляторов)

## Управление версией

### Версия приложения (VERSION_NAME)

Отображается в магазине приложений. Изменяется вручную в `gradle.properties`:

```properties
VERSION_NAME=1.0
```

Примеры версий:

- `1.0` - первый релиз
- `1.1` - минорное обновление с новыми функциями
- `1.3.4` - патч в рамках минора `1.3` (исправления багов без новых функций)
- `2.0` - мажорное обновление с изменениями в функционале

### Номер сборки (VERSION_CODE)

Автоматически увеличивается при каждом `make release`. Изменения вручную не требуется.

Формат: целое число, монотонно возрастающее.

```
VERSION_CODE=1
```

Пример:

```
VERSION_NAME=1.0, VERSION_CODE=1 → make release → VERSION_CODE=2 → AAB: swparks2.aab (1.0 build 2)
VERSION_NAME=1.0, VERSION_CODE=2 → make release → VERSION_CODE=3 → AAB: swparks3.aab (1.0 build 3)
VERSION_NAME=1.1, VERSION_CODE=3 → make release → VERSION_CODE=4 → AAB: swparks4.aab (1.1 build 4)
```

**Примечание:** Номер сборки (VERSION_CODE) никогда не сбрасывается при повышении версии приложения, поэтому он всегда уникален и монотонно возрастает.

## Публикация

- Для публикации в магазине приложений используется файл `swparks{VERSION_CODE}.aab`
- Для ручного распространения используются файлы:
  - `swparks{VERSION_CODE}-arm64-v8a.apk`
  - `swparks{VERSION_CODE}-armeabi-v7a.apk`

## Скриншоты

### Генерация скриншотов

Для генерации скриншотов выполните:

```bash
make screenshots
```

Эта команда:

1. Собирает APK для скриншотов (`:app:assembleDebug` + `:screenshot-tests:assembleDebug`)
2. Устанавливает геолокацию Москва на запущенном эмуляторе
3. Запускает fastlane для захвата скриншотов на эмуляторе
4. Генерирует скриншоты для локали `ru-RU` в папку `fastlane/metadata/android/`
5. Удаляет APK-артефакты и автоматически обновляет README.md (таблица скриншотов + версии)

**Важно:** Для успешного создания скриншотов необходимо чтобы был запущен эмулятор с соответствующими требованиями для RuStore:

- Соотношение сторон экрана: 9 x 16
- Рекомендуемое разрешение: 1080 х 1920

### Обновление README.md

После генерации скриншотов нужно выполнить команду для обновления таблицы скриншотов в README.md:

```bash
make update_readme
```

Эта команда автоматически:

1. Находит самые свежие файлы скриншотов по шаблону `{номер}-{описание}_{временнаяМетка}.png` (используется только локаль `ru-RU`)
2. Заменяет существующие теги `<img src="./fastlane/.../{номер}-{описание}_{временнаяМетка}.png">` в README.md на пути со свежим таймстампом
3. Обновляет версии в README.md (вызывает `updateReadmeVersions`)

Порядок работы:

```bash
# 1. Сгенерировать скриншоты (README.md обновится автоматически)
make screenshots

# 2. Зафиксировать изменения в гите
```

Отдельный запуск `make update_readme` нужен только если требуется обновить таблицу скриншотов или версии без генерации скриншотов.

### Чек-лист перед релизом

- [ ] Увеличен `VERSION_NAME` при необходимости
- [ ] Сгенерированы и обновлены скриншоты
- [ ] Выполнен `make release` и создан AAB-файл
